# Контекст проекта — для Claude Code

Конспект для продолжения работы в новом чате. Проект спроектирован в claude.ai,
затем несколько больших сессий в Claude Code довели его до текущего состояния.

## Что это за проект

Веб-версия личного трекера трат (наследник telegram-expense-bot) — PWA для
iPhone («Добавить на экран Домой»), с мгновенным streaming-распознаванием
голоса и работающая офлайн. UI копирует референс-приложение «Qalta»
(пользователь присылает скриншоты/видео из него и просит повторять 1:1,
вплоть до покадрового разбора анимаций).

- Репозиторий: `github.com/Esenzhan/expense-web` — монорепо: `frontend/`,
  `backend/` **и `bot/`** (Telegram-бот, см. «Telegram-бот» ниже; у бота
  никогда не было отдельного репозитория — `expense-bot` на GitHub не
  существует, локальный `.git` в его исходной папке указывал в никуда)
- Прод фронтенд: `https://expense-web-eosin.vercel.app` (Vercel, аккаунт
  `esenzhan`, scope `tommili1`, проект **`expense-web`** — см. предостережение
  про `vercel link` ниже)
- Прод бэкенд: `https://expense-web-peo6.onrender.com` (Render free tier,
  автодеплой из GitHub `main`). На Render в том же workspace есть ещё один,
  **не связанный** сервис с именем `expense-bot` (Python, сломанный деплой,
  не используется) — не путать при добавлении env-переменных, проверять по
  URL/типу сервиса, не по названию
- БД: Neon Postgres (проект `expense-web`)
- Вход на сайт: Google OAuth, закрытый список из 2 аккаунтов (см. раздел
  «Мульти-аккаунт» ниже)

## Стек и архитектура

```
iPhone PWA (standalone, офлайн-способный через sw.js)
  │ MediaRecorder webm/opus, чанки 250мс
  │ (клиент буферизует чанки до открытия WS + 700мс на рукопожатие
  │  сервер→Deepgram; первый чанк несёт заголовок контейнера!)
  ▼
WebSocket wss://…/ws/voice   ← при «стоп» клиент шлёт {"type":"stop"}
  │ реконнект-цикл ~80с если сокет не открылся (Render просыпается 30–50с)
  ▼
Deepgram streaming STT (language=ru, nova-2, interim_results, endpointing=500)
  │ partial → на фронт live; сервер тоже буферизует аудио до открытия DG-сокета
  │ стоп-маркер ИЛИ авто-финал (500мс тишины) → сервер сразу отпускает микрофон
  ▼
Claude Haiku (claude-haiku-4-5-20251001) парсит текст → {amount, category,
  wallet, description}; списки категорий и кошельков подставляются в промпт
  ИЗ БД (кэш 60с, инвалидация при изменениях)
  ▼
Сервер шлёт {type:"parsed", proposal} — НЕ сохраняет сам!
  ▼
Фронт показывает карточку подтверждения (Отмена/Сохранить) → POST /api/expenses
  (офлайн: POST падает → трата уходит в localStorage-очередь, синкается
  когда появится сеть — см. офлайн-раздел ниже)
```

- **Backend** (`backend/src`): Express + ws + pg + Anthropic SDK + googleapis,
  один процесс. Таблицы: `users` (по одной строке на Google-аккаунт из
  allowlist — email/name/google_sub/зашифрованный google_refresh_token/
  sheet_id/bot_api_key), `expenses` (теперь с `user_id`), `categories`
  (seed 10 штук на КАЖДЫЙ кошелёк — см. «Категории per-wallet» ниже,
  больше не единый общий список), `wallets` (seed: Личные/Семья/Бизнес/
  Ремонт; «Личные» — фолбэк, защищён; у каждого кошелька теперь есть
  `shared` — см. «Мульти-аккаунт» ниже). Роуты: `/api/auth/google/{start,
  callback}` + `/api/auth/me`, `/api/expenses` (GET с
  `?wallet=&from=&to=&limit=` / POST — принимает опциональный `created_at`
  для бэкфилла исторических трат с реальной датой вместо `now()` / PUT /
  DELETE — все требуют auth), `/api/stats/{summary,by-wallet,daily}`
  (summary принимает `?wallet=`, тоже требуют auth), `/api/categories`
  (GET публичный, принимает `?wallet=` — без него отдаёт ВСЕ категории
  всех кошельков с полем `wallet` в каждой строке, для одноразовой
  гидратации фронта и обратной совместимости; бот тоже дёргает, теперь
  всегда с `?wallet=`; POST/DELETE только с логином, DELETE теперь
  `/api/categories/:wallet/:name`), `/api/wallets` (аналогично; PUT
  переименовывает и переносит траты транзакцией; DELETE блокируется при
  наличии трат). **`/api/stats/insights` УДАЛЁН** — вся логика Инсайтов
  переехала на фронт (см. ниже), держать две реализации арифметики в синхроне
  оказалось лишним.
- **Frontend** (`frontend/src`): React + Vite, без UI-библиотек, стили в одном
  `styles.css`. Recharts УДАЛЁН — единственный график (Инсайты) нарисован
  вручную SVG (`InsightsChart.jsx`). Реестры категорий/кошельков —
  модульные сторы (`categoryIcons.js`, `wallets.js`) с hydrate из API +
  localStorage-кэш. `insights.js` — портированная 1:1 с бэкенда чистая
  арифметика (`computeInsights`, `periodRange`), теперь единственная копия.

## Мульти-аккаунт: Google-логин + шаринг кошельков (добавлено 2026-08-12)

Раньше сайт был однопользовательским (один общий Postgres на всех), а
Telegram-бот писал напрямую в Google Sheets — **две независимые базы**.
Теперь всё объединено: закрытый логин на сайте (2 аккаунта), бот пишет
через API сайта, обе стороны сходятся в одних и тех же данных.

- **Вход**: Google OAuth (`backend/src/routes/auth.js`,
  `services/googleAuth.js`), allowlist по email в env `ALLOWED_EMAILS`
  (только вы двое — открытой регистрации нет). Scope запрашивает не только
  identity, но и `spreadsheets`+`drive.file` — токен нужен бэкенду, чтобы
  писать в личный Sheet пользователя даже когда его нет на сайте (например
  когда трату шлёт бот). `prompt=consent` всегда форсит выдачу
  `refresh_token` (иначе Google отдаёт его только при самом первом
  согласии). JWT-сессия живёт 180 дней, хранится во фронте в
  `localStorage` (`traty-token`, см. `frontend/src/auth.js`), шлётся как
  `Authorization: Bearer`.
- **Личная Google-таблица**: при первом логине (`ensureUserSheet` в
  `services/sheets.js`) от имени пользователя создаётся Spreadsheet в ЕГО
  СОБСТВЕННОМ Google Drive (не в сервисном аккаунте) — `sheet_id`
  сохраняется в `users`. Формат листов 1:1 с тем, что раньше писал сам бот
  (`bot.py`'s `get_wallet_sheet`): вкладка на кошелёк, шапка `Дата, Время,
  Сумма, Категория, Описание, Источник, Кто, ID` — колонка `ID` (Postgres
  `expenses.id`) добавлена НОВОЙ, бот её не читает, но по ней бэкенд находит
  строку для update/delete.
- **Общие vs личные кошельки** (`wallets.shared`, boolean): Семья/Бизнес/
  Ремонт = `true`, Личные = `false`. Это работает НА ДВУХ уровнях
  одновременно:
  - **Сайт** (`routes/expenses.js`, `routes/stats.js`): траты общего
    кошелька видны и суммируются для ОБОИХ аккаунтов (`WHERE user_id=$me
    OR wallet = ANY(shared_names)`); личные — только у создателя. НО
    редактировать/удалять может только тот, кто СОЗДАЛ трату, даже в общем
    кошельке — чужая строка в `ExpenseList` рендерится с классом
    `.readonly` (тусклая, `pointer-events` не блокируются CSS, но клик
    просто не открывает `onSelect`) и бэкенд отдаёт 404 на чужой
    PUT/DELETE (сделано намеренно так — см. `[[dariya-workflow]]` про
    итеративные уточнения).
  - **Sheets**: общая трата зеркалится СРАЗУ в обе личные таблицы (кто бы
    её ни залогировал), с колонкой «Кто» = имя автора. Личная — только в
    таблицу автора, «Кто» пусто. Это заменило собой старый
    `RENOVATION_OWNER_EMAIL`-костыль (принудительная запись Ремонта в одну
    конкретную таблицу) — теперь это просто частный случай «Ремонт тоже
    shared», спец-код убран.
- **Бот** (`bot/bot.py`, живёт в этом же репо, деплой — см. ниже):
  `/addcategory` и `/deletecategory` УДАЛЕНЫ — категории только с сайта.
  Бот получает список категорий через `GET /api/categories` (кэш 60с),
  сохраняет трату через `POST /api/expenses` с заголовком `X-Bot-Key`
  (постоянный ключ на аккаунт, `users.bot_api_key`, сопоставлен с
  `USER1_TELEGRAM_ID`/`USER2_TELEGRAM_ID` в `.env` на VM — **однажды уже
  перепутали местами**, симптом был «сообщения Есенжана улетают в таблицу
  Дарии и наоборот», чинится свапом `USER1_BOT_KEY`/`USER2_BOT_KEY`).
  `/budget` и `/renovation` НЕ ТРОГАЛИ — по-прежнему читают Google Sheets
  напрямую через `gspread`+сервисный аккаунт (`GOOGLE_CREDENTIALS_FILE`),
  просто теперь эти таблицы заполняет бэкенд сайта, а не сам бот.
- **Postgres-миграция**: старая (тестовая, однопользовательская) история
  трат была намеренно стёрта (`TRUNCATE expenses`) при добавлении
  `user_id NOT NULL` — см. `initSchema()` в `db.js`, идемпотентно проверяет
  наличие колонки перед труном, повторно не сработает.
- **Env, которые добавились** (см. `backend/.env.example`):
  `GOOGLE_OAUTH_CLIENT_ID/SECRET/REDIRECT_URI`, `ALLOWED_EMAILS`,
  `JWT_SECRET`, `TOKEN_ENCRYPTION_KEY` (шифрует `google_refresh_token` в
  БД, AES-256-GCM, `services/crypto.js`). `RENOVATION_OWNER_EMAIL` больше
  не используется кодом (Ремонт и так shared), но может остаться висеть в
  Render — безвредно.
- **OAuth consent screen**: проект `adept-parsec-500611-h1` в Google Cloud
  (тот же, где сервисный аккаунт бота), Publishing status = **Testing**
  (осознанно — верификация у Google не нужна для 2 тестовых пользователей),
  оба email добавлены в Test users. Поле для test users в новом UI
  Google Auth Platform — это chip-input, для нескольких email нужно
  добавлять по одному с Tab/Enter между ними, а не через запятую одной
  строкой (иначе примет как один невалидный email).

## Категории — свой список на каждый кошелёк (добавлено 2026-08-12)

Раньше `categories` был ОДНИМ общим списком на все 4 кошелька. Теперь у
каждого кошелька независимый список (можно добавлять/удалять категории в
одном, не трогая остальные).

- **Схема**: `categories.wallet TEXT NOT NULL REFERENCES wallets(name)
  ON DELETE CASCADE ON UPDATE CASCADE`, уникальность теперь `UNIQUE
  (wallet, name)` вместо `UNIQUE(name)`. `ON DELETE/UPDATE CASCADE`
  обязательны — без них удаление или переименование кошелька падало бы
  500-й (FK violation), так как `routes/wallets.js` не чистит/не
  переносит категории вручную.
- **Миграция прод-данных**: старые общие категории разведены по всем 4
  кошелькам (каждый получил свою независимую копию исходных 10). Мигратор
  в `initSchema()` (`db.js`) **обязательно в транзакции** (`pool.connect()`
  + BEGIN/COMMIT/ROLLBACK, не отдельные `pool.query()`) — первая версия
  была НЕ транзакционной, дропала старый `UNIQUE(name)` ПОСЛЕ попытки
  разложить категории по кошелькам, поэтому падала на первой же вставке
  дубликата имени и роняла бэкенд НА КАЖДОМ старте (прод реально полежал
  в этом состоянии несколько минут). Детект «миграция не завершилась» —
  по `is_nullable` колонки `wallet` (NOT NULL выставляется только в конце
  успешной миграции), не просто по её наличию — иначе повторный старт после
  сбоя решил бы, что мигрировать уже не нужно, и застрял бы в разбитом
  состоянии навсегда.
- **Бэкенд**: новый `backend/src/categories.js` (кэш 60с, по образцу
  `wallets.js`) — `categoryNamesFor(wallet)`, `isValidCategory(wallet,
  name)`, `categoryNamesByWallet()`. Голосовой парсер (`parseExpense.js`)
  теперь в ОДНОМ вызове Claude передаёт карту «кошелёк → его категории» и
  просит модель выбрать категорию именно из списка выбранного кошелька;
  фолбэк при несовпадении — «Прочее» ЭТОГО кошелька, не общее.
- **Бот** (`bot/bot.py`, задеплоен на VM): `get_categories(wallet)`
  дёргает `GET /api/categories?wallet=` с уже определённым через
  `detect_wallet()` кошельком (раньше был один глобальный список +
  хардкод `WALLETS` только для «Ремонт»); хардкод остался как чисто
  офлайн-фолбэк на случай недоступности сайта.
- **Фронт**: `CategoriesSheet` получил переключатель кошельков (вкладки
  сверху, независимо от того, какой кошелёк выбран на главном экране) и
  удаление категории (тап → «✕» → «Точно?» → тап ещё раз; «Прочее»
  защищено). `categoryIcons.js` хранит реестр как `{ [wallet]: [...] }`,
  `listCategories(wallet)`/`getCategoryIcon(wallet, name)` требуют
  кошелёк первым аргументом — при добавлении нового места, где рисуется
  иконка категории, не забывать передавать его (легко забыть и получить
  иконку не того кошелька). Карусель категорий в `EditExpenseSheet`
  пересобирается и перецентровывается при смене кошелька в `<select>`.
- **Иконки** (`CategoryGlyph.jsx`): было 10 глифов (только сид-категории),
  теперь ~78 — покрыт КАЖДЫЙ emoji из пикера `NewCategorySheet`
  (`ICON_GROUPS`), плюс сам пикер и «Рекомендации» (было «Suggestions»)
  теперь тоже рисуют `CategoryGlyph`, а не сырой emoji — выбор в UI сразу
  выглядит так же, как сохранённая категория. При добавлении новых иконок
  проверять НЕ в маленьком превью (32px не показывает реальную форму —
  так пицца без корочки выглядела ровным треугольником, а баг с лишним
  `H`-командой в пути скутера был не виден вовсе), а рендерить каждую
  ОТДЕЛЬНО крупно (150px+) через временный харнесс — см. «Как тестировать
  без телефона». Мелкие окружности (r ≲ strokeWidth) поверх другого
  пересекающегося пути визуально сливаются в кляксу вместо кольца — так
  сломались колёса скутера, наложенные на линию палубы.

## Telegram-бот (`bot/`)

Раньше был отдельным проектом на Oracle VM без места в git (см. выше —
`expense-bot` на GitHub не существовал). Теперь код лежит в этом репозитории
под `bot/`, но **деплой всё ещё полностью ручной**, ничего не триггерится
пушем в `main`:

```bash
scp -i ~/Downloads/ssh-key-2026-07-06.key bot/bot.py bot/requirements.txt \
  ubuntu@217.142.234.123:~/expense-bot/
ssh -i ~/Downloads/ssh-key-2026-07-06.key ubuntu@217.142.234.123 \
  "cd ~/expense-bot && source venv/bin/activate && pip install -r requirements.txt && sudo systemctl restart expense-bot"
```

Живёт как systemd-сервис `expense-bot` на VM `217.142.234.123` (Oracle Cloud
Always Free). `.env` и `credentials.json` — только на VM, в git не входят.
Один хардкод, на который однажды напоролись: `.env` на VM был без
завершающего перевода строки — дописанные через `>>` переменные слиплись с
последней строкой в одну (`GOOGLE_CREDENTIALS_FILE=credentials.jsonAPI_BASE_URL=...`)
и молча не распарсились. Проверять `cat -A .env | tail` после любого append.

## Экраны и фичи (всё уже на проде)

- **Главная**: чип кошелька (тап → шторка «Счета»), 4 круглые кнопки в шапке
  (поиск/статистика/кошельки — визуальные заглушки, шестерёнка работает),
  карточка «Расходы за» с переключателем периода (месяц/7/30) и кнопкой
  «✦ Инсайты», список трат по датам (новые строки анимированно вплывают —
  fade+slide, keyed по id так что повторный рендер не триггерит анимацию
  у старых строк), док из 3 кнопок (скан-заглушка → открывает ручной ввод,
  микрофон 77px, «+»).
- **Иконки категорий**: минималистичные ОДНОЦВЕТНЫЕ line-glyph'ы (не эмодзи!),
  `CategoryGlyph.jsx` — SVG-путь почти на каждый emoji, который можно
  выбрать в пикере (~78 штук, см. «Категории per-wallet» выше), красится
  через `currentColor` в `fg`-цвет категории. Emoji вне этого набора
  (напечатанный вручную через системную emoji-клавиатуру) рендерится как
  сам emoji — фолбэк.
- **Свайп-удаление трат + отмена** (`ExpenseRow.jsx`): свайп строки влево —
  красная зона растёт вместе с пальцем (не revealed-button, который потом
  нужно тапать отдельно), после `COMMIT_DISTANCE` — хаптик и удаление сразу
  по отпусканию. Жест на один тач залипает на оси (`h`/`v`), решается один
  раз и не пересматривается — иначе диагональный свайп дёргает то строку,
  то скролл списка. Удаление ВСЕГДА отложенное (`App.jsx`:
  `requestDeleteExpense`/`commitDelete`/`undoDelete`): строка прячется из
  UI сразу, но DELETE на сервер уходит только через `UNDO_WINDOW_MS` (4с)
  — «Отменить» просто гасит таймер, ничего не переcоздавая. Баннер сверху
  («Операция удалена — Отменить», кольцо-таймер, СЧИТАЕТСЯ не крутится)
  `position:fixed` к вьюпорту (НЕ в потоке `.app` — иначе при скролле вниз
  списка баннер уезжает вместе со страницей и его не видно). Тот же
  отложенный путь используется и кнопкой «Удалить» в `EditExpenseSheet`
  (`onDeleteRequested`) — единая логика отмены везде. Traты, ещё не
  синхронизированные (`pending`, из офлайн-очереди), удаляются НЕМЕДЛЕННО
  без окна отмены — отменять там нечего, DELETE ещё не уходил.
- **Живое обновление**: бот пишет траты напрямую в Postgres, сайту об этом
  никто не сообщает — открытая вкладка поллит `refreshAll` каждые 15с, пока
  видима, плюс сразу при возврате в форграунд (тот же эффект, что и синк
  офлайн-очереди).
- **Кэш по (период, кошелёк)** (`App.jsx`, `dataCacheRef`, в памяти на
  сессию): переключение между уже посещёнными комбинациями кошелёк+период
  мгновенное (рисуется из кэша, сеть дёргается в фоне и тихо подменяет),
  вместо полного ожидания сети при каждом клике.
- **Офлайн-первый холодный старт**: раньше всё приложение ждало ответа
  `fetchMe()` (единственный запрос без офлайн-фолбэка) — на холодном
  Render (30–50с) или реальном офлайне это был пустой экран, а любая
  сетевая ошибка там ошибочно разлогинивала. Теперь последний известный
  пользователь кэшируется в `localStorage` (`traty-last-user`) и рисуется
  СРАЗУ без сети; `fetchMe()` уходит в фон только подтвердить/обновить.
  Разлогинивает по-прежнему ТОЛЬКО настоящий 401 (событие
  `traty:unauthorized`), не любой fetch-фейл.
- **Голос**: тап микрофона → live-транскрипт → карточка подтверждения.
  Отмена записи ✕. Fallback-таймер 15с (или до 80с если сокет ещё
  переподключается — Render холодный старт). При авто-финале (тишина)
  микрофон отпускается сразу, не ждёт ответа Claude — на iOS иначе индикатор
  записи в статус-баре не гас.
- **Ручной ввод/редактирование** (`EditExpenseSheet`, `position:absolute`,
  почти во весь экран, всё — кошелёк/заметка/карусель/клавиатура/Сохранить —
  прижато к низу как в референсе): настоящий ЦЕПНОЙ калькулятор (не просто
  +−×÷ пара чисел) — вся цепочка токенов хранится и вычисляется строго
  слева направо (БЕЗ приоритета операций, как в референсе), показывается
  строкой-выражением над суммой; повторный тап оператора его меняет; ⌫
  откатывает по шагам. useReducer — НЕ useState (была потеря нажатий из-за
  батчинга). Ввод цифры анимирован (fade+scale-in новой цифры, FLIP-разъезд
  цифр/₸ от центра). Карусель категорий со snap к центру: выбранная плитка
  scale 1.4×, невыбранные 0.9×, рост строго вблизи центра (дед-зона —
  0.8 шага — чтобы сосед не оставался чуть увеличенным в покое). Геометрия
  карусели — ТОЛЬКО `getBoundingClientRect`, не `offsetLeft` (см. хардкод
  ниже). Закрытие (крестик/фон/Сохранить/Удалить) — единая slide-down
  анимация 300мс + гаснущий фон; при Сохранить/Удалить список обновляется
  ДО старта анимации закрытия (`onCommitted`), чтобы новая строка уже стояла
  на месте за уезжающей шторкой. Тап по строке траты открывает редактор.
  Работает офлайн (см. ниже).
- **Инсайты** (`InsightsSheet`): открывается тапом ИЛИ тягой вниз из любого
  места главной (только при scrollY=0; кнопка растягивается по мере тяги,
  звезда растёт до 4× и центрирована — gap коллапсит вместе с текстом).
  Портал в `document.body` (НЕ внутри `.app` — см. хардкод про transform).
  Почти во весь экран (position:absolute, top:7dvh, bottom:0). Данные
  считаются ЦЕЛИКОМ НА КЛИЕНТЕ (`insights.js`) из уже закэшированных строк
  трат — мгновенное открытие без сети, пересчёт после каждой операции
  (App.jsx держит фоновый кэш строк периода и сливает с офлайн-очередью).
  График — две линии: пунктир «план» (равномерный темп до месячного лимита,
  который задаётся тут же кнопкой-пилюлей, хранится в localStorage на
  кошелёк) и сплошная «факт»; под графиком — отклонение от плана (красным
  превышение / зелёным запас). 6 карточек метрик.
- **Настройки** (`SettingsSheet`, страница въезжает справа): все секции из
  референса; работают: Категории, Экспорт CSV (реальный), 5 переключателей
  (persisted в localStorage). Остальное — визуальные строки. Pro-баннер и
  чужие соцсети НЕ копировали.
- **Категории** (`CategoriesSheet` + `NewCategorySheet`): список с ручками
  (перетаскивание НЕ реализовано, только вид), создание своей категории:
  имя + live-превью, палитра 12 цветов, сетка emoji по группам,
  Suggestions по ключевым словам («Дом и быт» → 🏠🛋️🛏️…).
- **Счета** (`WalletsSheet` + `NewWalletSheet`): «Все счета» + список с
  суммами месяца, выбор фильтрует ВСЮ главную (чип/сумма/список/Инсайты,
  persisted), карандаш → редактирование, «+» → создание (те же
  палитра/иконки/Suggestions). Новые счета/категории сразу доступны голосу.
- **Шторки** (`sheetGestures.js`): все закрываются свайпом вниз (только когда
  внутренний скролл наверху; горизонтальные тяги не перехватываются —
  карусель), затемнение гаснет пропорционально тяге, размонтирование по
  transitionend. Скролл фона глушится НА УРОВНЕ КАСАНИЙ (preventDefault на
  затемнении + overscroll-behavior) — position:fixed на body ломает iOS
  (шторка всплывает над низом), overflow:hidden сбрасывает скролл.
- **Офлайн-режим** (новое, весь стек продуман под «убил PWA в самолётном
  режиме → открыл → пользуется»):
  - `public/sw.js` кэширует HTML-shell network-first (иначе редеплой залипает
    на старой версии; фоллбек на кэш только при реальном офлайне) и хэшируемые
    ассеты (js/css/иконки) stale-while-revalidate. Регистрируется в `main.jsx`.
  - Ручной ввод трат работает без сети: `offlineQueue.js` — POST падает →
    трата уходит в localStorage-очередь (`traty-pending-expenses`), рендерится
    как обычная строка с флагом `pending`, до подтверждения от сервера.
  - Синхронизация очереди: НЕ полагается только на событие `online` или
    `visibilitychange` — на iOS Safari (особенно standalone PWA) они
    ненадёжны. App.jsx дополнительно ПОЛЛИТ каждые 15с, пока в очереди
    что-то есть.
  - Инсайты и главный экран — см. выше, полностью локальная арифметика.

## Захардкоженные знания о платформе (не переоткрывать!)

- **Вибрация на iOS Safari**: Vibration API нет. Хак — программный клик по
  label скрытого `<input type="checkbox" switch>` (`haptics.js`). Из НАСТОЯЩИХ
  click-обработчиков работает надёжно (iOS 17.4–26.4). Из touch-обработчиков
  (карусель-тик при скролле) — попытка есть, но по опыту iOS такое обычно
  блокирует; не гарантировано, могло не сработать на текущей версии iOS
  пользователя — не удивляться отсутствию вибрации на скролле.
  setTimeout-отложенный клик убивает даже рабочие случаи (только
  `hapticHeavy` — двойной клик — использует один отложенный на 120мс, это
  ещё держится). На Android — navigator.vibrate везде, надёжно.
- **iOS PWA восстанавливается из памяти** без перезагрузки — пользователь
  может видеть старую версию, пока не убьёт приложение из переключателя.
  Для смены ИКОНКИ на экране Домой этого НЕДОСТАТОЧНО — iOS кэширует иконку
  с момента добавления, нужно удалить с экрана Домой и добавить заново.
- **Deepgram**: финализирует фразу только по ≥500мс тишины В ПОТОКЕ или по
  CloseStream. Обрыв аудио без стоп-маркера = вечное «Обрабатываю…».
  Аудио, пришедшее до открытия сокета (клиентского или серверного к DG),
  раньше молча ДРОПАЛОСЬ — терялся заголовок контейнера и весь поток
  становился непарсибельным. Теперь буферизуется с обеих сторон.
- **Service worker**: HTML — network-first, хэшированные ассеты —
  stale-while-revalidate. Ловушка при клонировании Response: `.clone()`
  обязан случиться в САМОЙ ПЕРВОЙ реакции на `fetch()`, до того как
  потребитель `respondWith` (браузер, рендерящий навигацию) начнёт читать
  тело — иначе гонка и «body is already used», кэш молча не пишется.
- **Vercel**: аккаунт залогинен в CLI (`esenzhan`). Проект **`expense-web`**
  на Vercel настроен с **Root Directory = `frontend`** — значит
  `npx vercel deploy --prod --yes` нужно запускать из КОРНЯ репозитория, НЕ
  из `frontend/` (запуск изнутри `frontend/` даёт ошибку
  «Root Directory "frontend" does not exist», т.к. Vercel тогда ищёт
  `frontend/frontend`). И корневой `.vercel/project.json`, и
  `frontend/.vercel/project.json` указывают на один и тот же
  `projectId`/`expense-web` — привязка не потеряна, дело только в том, откуда
  запускать команду. ОПАСНОСТЬ: обычный `npx vercel deploy` без явной
  привязки может создать/задеплоить в НОВЫЙ проект (однажды случайно возник
  лишний проект «frontend» в том же scope) — если `vercel ls` показывает не
  тот проект, перелинковать `npx vercel link --yes --scope tommili1
  --project expense-web`. Частый curl на прод-домен ловит Vercel Security
  Checkpoint (антибот) — проверять через браузер/browser-пейн, не
  curl-полингом самой HTML-страницы (статические ассеты типа
  `/icon-512.png` curl'ить можно).
- **Render free tier**: холодный старт 30–50с (иногда дольше) — все
  таймауты/буферы (WS-реконнект, fallback-таймеры голоса) это учитывают.
  Фронт шлёт fire-and-forget GET `/api/health` при открытии приложения и по
  возврату в форграунд, чтобы будить сервер заранее.
- **Деплой теперь ПОЛНОСТЬЮ автоматический через один `git push`**: Vercel
  подключён к GitHub и передеплоивает фронт на пуш в `main` сам по себе —
  ручной `npx vercel deploy --prod --yes` из корня репо, который раньше был
  обязательным шагом, БОЛЬШЕ НЕ НУЖЕН (Render и так уже автодеплоил бэкенд).
  Проверять фактически раздаваемый бандл всё равно нужно (см. «Как
  тестировать» ниже) — Vercel-деплой занимает ~10–40с после пуша.
- **Флекс-контейнер, который сам скроллится (`overflow-x/y: auto`),
  ВНУТРИ другого флекс-контейнера с ФИКСИРОВАННОЙ высотой** (например,
  `height: 92vh`): по спецификации его «автоматический минимальный
  размер» по поперечной оси считается НУЛЁМ, а не по контенту — если
  соседям по общей колонке не хватает места, `flex-shrink` схлопывает
  именно такой элемент в его же паддинг, а не пропорционально всем.
  Дважды ловили на этом (`.wallet-tabs`, затем `.newcat-suggestions`/
  `.palette-row`) — лечится явным `min-height` на самом скроллящемся
  элементе, полагаться на высоту контента внутри нельзя.
  `.wallet-tabs` в итоге вообще переведён на `flex-wrap: wrap` вместо
  скролла — так безопаснее и последовательнее с остальным UI
  (`.period-toggle` уже так делал).
- **`InsightsButton`** слушает `touchstart/move/end` на `document`
  ЦЕЛИКОМ (чтобы тянуть шторку вниз можно было с любого места главного
  экрана), с исключающим списком селекторов (`.sheet-backdrop`,
  `.recorder-dock` и т.п.), которые не должны участвовать в этом жесте.
  Любая НОВАЯ область со своим тач-жестом (например `.expense-row-wrap`
  для свайпа-удаления) должна попасть в этот список, иначе оба
  распознавателя жеста дерутся за один и тот же touch при малейшем
  вертикальном дрожании пальца во время горизонтального свайпа.
- **iOS Safari не чистит Cache Storage/service worker при удалении
  PWA-иконки с экрана Домой и повторном добавлении** — они привязаны к
  origin, а не к иконке, старый бандл может продолжать раздаваться. Для
  реального сброса — Настройки → Safari → Дополнительно → Данные сайтов
  → удалить для домена (или сначала проверить в приватной вкладке Safari,
  что дело именно в кэше, а не в реальном баге).

## Как тестировать без телефона

- Синтез русской речи: `say -v Milena -o x.aiff "текст"` + `afconvert -f WAVE
  -d LEI16@16000 -c 1`. Честный тест голосового потока — страница в
  браузер-пейне, WAV → WebAudio → MediaStreamDestination →
  MediaRecorder(webm/opus) → прод-WS (скрипт эфемерный, пересоздавать по
  надобности).
- Жесты/скролл в браузер-пейне: синтетические TouchEvent/Touch или прямые
  DOM-манипуляции (`scrollTo`, dispatch `MouseEvent` на кнопки) — реального
  тач-скролла эмулятор не даёт, но для проверки логики (не плавности)
  достаточно.
- Офлайн — НЕ полагаться на devtools-подобный офлайн-тумблер (browser-пейн
  его не даёт); эмулировать патчем `window.fetch`, что для сетевых запросов
  на прод-домен кидает reject — но это НЕ проверяет service-worker'ный
  network-layer (SW живёт в отдельном контексте, page-level monkeypatch его
  не трогает) — для проверки самого офлайн-шелла (SW) нужен реальный
  офлайн/самолётный режим на телефоне.
- Кадры из видео-референсов: swift-скрипт с `AVAssetImageGenerator`
  (эфемерный, в `scratchpad/` текущей сессии — пересоздавать по надобности).
  Для покадрового разбора конкретных моментов — вырезать частоту кадров
  повыше (30fps) в узком временном окне, а не весь ролик через 10fps.
- В браузер-пейне таймеры/анимации троттлятся — замеры «через N мс» врут,
  доверять итоговому состоянию DOM/computed style, не таймингу.
- После любого прод-деплоя (просто `git push`, см. хардкод про Vercel
  autodeploy) — дождаться, что фактически отдаваемый бандл (`curl` на
  `/`, вытащить хэш `<script src>`) сменился по сравнению с тем, что было
  до пуша, прежде чем тестировать — Vercel-деплой занимает ~10–40с, а
  вручную открытый браузер-пейн может показать старый HTML ещё пару
  секунд после этого.
- Для проверки НОВОГО React-компонента (особенно визуально/CSS) без
  логина и без прохождения всего приложения — временный отдельный
  vite-энтрипоинт: `frontend/test-X.html` + `frontend/src/test-X-main.jsx`
  (обычный `ReactDOM.createRoot(...).render(<Компонент ... />)` с
  моковыми пропсами), открыть в браузер-пейне на `localhost:5173/test-X.html`
  через `preview_start`. Обязательно удалить оба файла и проверить
  `git status`, прежде чем коммитить — они не для репозитория. Так же
  можно быстро вывести на экран одиночный SVG-глиф в реальном размере
  (150px+) через `javascript_tool` → `document.body.innerHTML = '<svg ...>'`
  — не полагаться на маленький thumbnail в общей галерее иконок, там
  форма/баги не видны (см. «Категории per-wallet» про иконку скутера).
- Массовая загрузка исторических данных (бэкфилл трат с реальными датами)
  — НЕ через прямой доступ к БД (обычно недоступен локально) и не через
  `X-Bot-Key` (в этой сессии его не было под рукой). Рабочий путь: открыть
  прод-сайт в браузер-пейне, попросить пользователя залогиниться самому
  через Google, затем `javascript_tool` → `fetch(API, { headers:
  { Authorization: 'Bearer ' + localStorage.getItem('traty-token') } })`
  прямо из вкладки — токен никогда не покидает браузер пользователя, а
  каждая запись идёт через настоящий `POST /api/expenses` (валидация,
  зеркалирование в Google Sheet и т.д.), просто с явным `created_at`.

## Стиль работы с пользователем

Пользователь (Дария, иногда пишет и Есенжан — оба на allowlist) присылает
скриншоты/видео из Qalta и просит копировать точь-в-точь — вплоть до
присылки видео с просьбой разобрать анимацию покадрово; тестирует ТОЛЬКО
на iPhone (PWA с экрана Домой) и отвечает коротко («опять завис», «сделай
так же»). Прод-первый цикл: коммит → **один `git push origin
master:main`** — Render и Vercel ОБА автодеплоят сами, ручной `vercel
deploy` не нужен (см. хардкод выше) → самопроверка на проде (curl на
изменившийся хэш бандла + браузер-пейн, мобильный вьюпорт) → просьба
проверить на телефоне, с напоминанием убить PWA из переключателя (iOS
